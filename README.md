# 🛏️ GCode Bed Off — Automatic Heated Bed Shutdown

![Python](https://img.shields.io/badge/python-3.6%2B-blue)
![License](https://img.shields.io/badge/license-MIT-green)

A small post-processing script that turns off the heated bed a few
minutes before your print actually finishes. Handy if you print multiple
pieces back-to-back: the bed starts cooling earlier, so it's ready to
remove your part and start the next print sooner.

It works by reading the time estimates your slicer already embeds in the
gcode (`M73 P.. R..` or `;TIME_ELAPSED:`) and inserting an `M140 S0`
command at the right point. **No slicer settings need to change** — these
estimates are on by default in virtually every modern slicer.

Supports plain `.gcode` as well as Bambu Studio's `.gcode.3mf` (including
files with multiple plates).

---

## Features

- ✅ Works with Bambu Studio, PrusaSlicer, SuperSlicer, OrcaSlicer, Cura
- ✅ Handles both plain `.gcode` and zipped `.gcode.3mf` files
- ✅ Automatically processes every plate in a multi-plate `.gcode.3mf`
- ✅ No dependencies — pure Python 3 standard library
- ✅ Configurable threshold (default: 5 minutes before end)

## Requirements

- Python 3.6+
- No external libraries needed

## Installation

```bash
git clone https://github.com/<your-username>/gcode-bed-off.git
cd gcode-bed-off
```

## Usage

```bash
python3 bed_off_gcode.py input_file [-o output_file] [-m minutes]
```

**Examples:**

```bash
# Plain gcode, default 5-minute threshold
python3 bed_off_gcode.py print.gcode

# Bambu Studio project, custom threshold
python3 bed_off_gcode.py plate.gcode.3mf -m 3

# Custom output filename
python3 bed_off_gcode.py print.gcode -o print_final.gcode
```

By default, the output is saved as `<name>_bedoff.<extension>` in the
same folder as the input.

## Slicer-specific notes

### Bambu Studio
Nothing to enable — `M73` progress commands are generated by default.
Export as `.gcode.3mf`, run the script on it, then print the resulting
`_bedoff.gcode.3mf` **directly** (e.g. from SD card). Re-slicing or
re-sending the original project will overwrite your changes, so make sure
you're printing the post-processed file itself.

> Note: Bambu Studio's UI won't show any marker for the inserted command
> (left/right sidebars) — this is expected, since the app doesn't re-parse
> raw gcode for manually inserted commands. The printer still executes it
> normally.

### PrusaSlicer / SuperSlicer / OrcaSlicer
`M73` is generated by default in most firmware profiles. If your exported
file is missing it, check **Printer → Custom G-code** for a modified
end-of-print script that might strip it out.

### Cura
Uses `;TIME_ELAPSED:` comments instead, which the script also supports
as a fallback. Enabled by default — check under **Preferences → Settings**
if a post-processing plugin is removing it.

## Verifying it worked

The script prints a summary after running:

```
Modified 'Metadata/plate_1.gcode' (method used: M73 R<minutes remaining>).
File saved to: print_bedoff.gcode.3mf
```

If a plate/file doesn't appear in the list, no valid insertion point was
found for it (e.g. the print is shorter than the chosen threshold).

## Limitations

- The remaining time is a **slicer estimate**, not a real-time measurement
  — actual deviation can be a few minutes depending on pauses, retracts,
  or speed changes during the print.
- You need to re-run the script every time you re-export/re-slice —
  it's not a persistent slicer setting.
